# Embedding Visualizer

Локальная тула для исследования произвольных наборов эмбеддингов. Реализованы
все этапы локального MVP: импорт и проверка данных, карта, проекции, кластеры,
соседи, срезы по metadata, кеш, сохранение исследований и экспорт. Есть адаптер
ограниченного снимка статической YT-таблицы.

## Запуск

Из папки проекта с подготовленным окружением:

```bash
./run.sh
```

Открыть <http://127.0.0.1:8501>. Пример `data/example` открывается автоматически,
другой набор можно выбрать в боковой панели. Центр экрана занимает карта;
настройки находятся слева, карточка объекта и соседи — справа. Панели можно
свернуть. Выбор точки обновляет карточку и подсветку без пересоздания карты:
масштаб и положение сохраняются.
По умолчанию включена тёмная тема с увеличенными элементами управления;
светлая тема переключается кнопкой в верхней панели. Размер точек регулируется
над картой. Выделение сохраняет цвет кластера (или базовый цвет без кластеризации)
и подчёркивается размером и обводкой.
Остановка — `Ctrl+C` в терминале сервера.

Для установки заново (проверено на Python 3.14, macOS ARM64):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install -e .
.venv/bin/visualizer demo
./run.sh
```

`requirements.lock` фиксирует проверенные версии, включая зависимости тестов.
Для разрешения подходящих версий на другом поддерживаемом Python:
`.venv/bin/python -m pip install -e '.[dev]'`.
Сервер по умолчанию слушает `127.0.0.1`. Все данные и вычисления остаются локально;
Plotly загружается из установленного Python-пакета, внешние CDN не используются.
Сервер — Python, интерфейс — HTML/CSS/JavaScript без сборки и Node.js.

## Исследование

- **Карта:** исходные координаты, PCA, UMAP и t-SNE. Для исходных векторов и PCA
  доступны любые две координаты. Можно выделять точки рамкой и лассо.
- **Соседи:** точный поиск по всему набору с cosine similarity, L2 или dot product.
  Сам объект исключается; соседи считаются по векторам до проекции карты.
- **Кластеры:** KMeans, HDBSCAN, Spectral, Agglomerative, DBSCAN и Gaussian Mixture
  в исходном пространстве или отдельном PCA.
  Цвета карты показывают кластеры; ниже доступны размеры, представители и
  статистики metadata, включая отдельную группу шума HDBSCAN/DBSCAN.
- **Автоподбор:** выберите алгоритм, число кластеров, критерий и бюджет до 6/12/24
  вариантов. Для KMeans, Spectral, Agglomerative и Gaussian Mixture подбираются
  параметры с минимальным внутрикластерным разбросом (SSE) либо максимальным
  Silhouette. Пространство и число кластеров фиксированы на весь поиск.
  Видны прогресс, оценки вариантов и параметры победителя; их можно перенести
  в ручной режим. Отмена сохраняет предыдущий результат. DBSCAN/HDBSCAN
  доступны в ручном режиме: они не задают точное число кластеров.
- **Нормализация:** явный переключатель L2 в боковой панели. Смена настройки
  сбрасывает проекцию и кластеры; выбранный ID сохраняется.
- **Срезы:** числовые диапазоны, категории, boolean, null и отсутствующие поля.
  Фильтр отображения сохраняет координаты и кластеры. Пересчёт на срезе запускается
  отдельно. Область поиска соседей — весь набор или текущий срез.
- **Окраска:** любое поле metadata или кластер; числовая шкала либо категории.
- **Исследования:** файл `.npz` сохраняет точные координаты, метки, параметры,
  фильтры, выделенные ID и вид карты. При открытии проверяется fingerprint данных.
- **Экспорт:** выделенные объекты, текущий срез или весь набор в CSV/Parquet,
  с ID, metadata, координатами и метками кластеров.

На странице видны фактически применённые параметры. Изменение полей формы
применяется по кнопке; переключение карты не меняет уже вычисленные кластеры.
Вычисления идут в фоне; картой можно пользоваться, пока строится проекция.
Подробности геометрии, API и ограничений: [docs/exploration.md](docs/exploration.md).

## Датасет

```text
my-dataset/
  dataset.parquet
  manifest.json
```

| Поле таблицы | Логический тип | Требование |
| --- | --- | --- |
| `id` | string | Уникальная непустая строка |
| `embedding` | list of numbers | Одинаковая длина, конечные значения float32 |
| `name` | string или null | Необязательная подпись |
| `metadata` | JSON object или null | Необязательные атрибуты |

```json
{
  "schema_version": 1,
  "dataset_name": "My embeddings",
  "space_id": "model-v1:output-layer",
  "version": "snapshot-001",
  "embedding_dim": 128,
  "default_metric": "cosine"
}
```

В каноническом Parquet векторы — fixed-size list float32, metadata — строка
с JSON-объектом. Reader также принимает Arrow struct и обычные числовые списки.
Полный контракт и Python API: [docs/dataset-format.md](docs/dataset-format.md).

## Проверка без интерфейса

```bash
.venv/bin/visualizer validate data/example
.venv/bin/visualizer validate data/example --json
```

Можно передать Parquet-файл с `manifest.json` рядом. Ошибки возвращают код 2
и диагностическое сообщение. Недопустимые строки не удаляются молча.

## Конвертация NumPy

Список ID задаёт порядок рядов матрицы; метаданные сопоставляются по ID:

```bash
.venv/bin/visualizer convert-npy \
  --embeddings /path/to/embeddings.npy \
  --ids /path/to/ids.json \
  --metadata /path/to/metadata.parquet \
  --id-column hid \
  --name-column category_name \
  --output data/my-embeddings \
  --dataset-name 'My embeddings' \
  --space-id 'model-v1:output-layer' \
  --version 'snapshot-001'
```

- Матрица: двумерный числовой `.npy`, без pickle.
- ID матрицы: JSON-массив или одномерный `.npy` без pickle.
- Метаданные: Parquet, CSV с заголовком или JSON-массив объектов.
- Все ID матрицы и метаданных должны совпадать; дубликаты запрещены.
- Целочисленные ID переводятся в строки. Строки, включая ведущие нули,
  сохраняются дословно. Bool и дробные ID запрещены.
- Дополнительные колонки складываются в `metadata`; конфликт с уже существующим
  ключом внутри объекта приводит к ошибке.
- CSV сохраняет значения строками; для типов используйте Parquet/JSON.

Если списка ID нет, вместо `--ids` нужен `--assume-row-order`: это подтверждение,
что порядок метаданных точно совпадает с матрицей. Проверяется число строк,
но доказать семантическое соответствие без ID невозможно.

Для замены существующего датасета нужен `--overwrite`. Проверка входных данных
завершается до записи результата.

## YT

Импорт доступен в боковой панели и через `visualizer import-yt`. Дополнительный
SDK устанавливается отдельно: `.venv/bin/python -m pip install -e '.[yt]'`.
Поддерживаются статические таблицы, явное сопоставление колонок и ограниченный
интервал строк. Токены берутся из стандартной конфигурации SDK и не сохраняются
в датасете или исследовании. [Инструкция и пример CLI](docs/yt.md).

## Настройки

В `visualizer.toml` заданы `data_dir`, `cache_dir`, `address` и `port`.
Относительные пути разрешаются относительно файла настроек.

```bash
.venv/bin/visualizer serve --config visualizer.toml --port 8502
.venv/bin/visualizer serve --data-dir /path/to/datasets --cache-dir /path/to/cache
```

Приоритет: CLI → переменные окружения → TOML → значения по умолчанию.
Переменные: `VISUALIZER_DATA_DIR`, `VISUALIZER_CACHE_DIR`, `VISUALIZER_ADDRESS`,
`VISUALIZER_PORT`. В `cache_dir/numba` сохраняется кеш компиляции UMAP,
в `cache_dir/results` — результаты операций. Ключ включает содержимое набора,
версию, параметры, seed, нормализацию, состав среза и версии библиотек.
Исследования сохраняются отдельными файлами через интерфейс. Они ссылаются на
исходный снимок данных; сами эмбеддинги в файл исследования не копируются.

## Структура

```text
src/embedding_visualizer/
  adapters/      # внешние источники → общий контракт
  data/          # контракт, проверки, чтение и запись Parquet
  compute/       # нормализация, проекции, кластеры, соседи, статистики
  web/           # HTTP API и постоянная HTML/Plotly-карта
  workspace.py   # состояние исследования и фоновые вычисления
  persistence.py # fingerprint, кеш, исследования, экспорт
  cli.py         # serve, validate, convert-npy, import-yt, demo
  settings.py    # переносимые настройки
tests/
docs/
```

Вычислительное ядро не зависит от интерфейса. Данные, кеш, окружение и локальные
настройки исключены через `.gitignore`. Абсолютных путей этой машины и
Arcadia-интеграции в исходниках нет.

## Проверки

```bash
.venv/bin/python -m pytest
.venv/bin/python -m pip check
```

Проверяются повреждённые данные, ID alignment, round-trip Parquet, защита от
перезаписи, конфигурация, CLI, численные результаты, срезы и кеш, точное
восстановление исследования, экспорт, изоляция сессий и HTTP API. YT-адаптер
тестируется с имитацией SDK; реальное подключение требует вашего кластера и таблицы.
